# Hangang admin UI 후보

[문서 목록](../../README.md)

세 페이지는 서버 연결 없이 브라우저에서 열 수 있는 디자인 검토용 예시다. 모든 수치, 계정, 호스트와 변경은 가상 데이터다. 실제 관리 화면이나 인증 흐름을 변경하지 않는다. 사이드바는 검토 페이지 내 상태·라우트·보안·변경 영역으로 이동하며, 적용 버튼은 실제 API를 호출하지 않는다.

| 후보 | 의도 | 강점 | 고려할 점 |
| --- | --- | --- | --- |
| [01 River](01-river.html) | 밝은 슬레이트와 청록, 차분한 운영 화면 | 상태·정책·변경을 일정한 카드와 표로 표현. 일상 관리에 적합 | 야간 관제에서는 기존 다크 테마와 같은 토큰 체계 필요 |
| [02 Nightwatch](02-nightwatch.html) | 네이비와 민트, 관제 중심 | 실시간 지표와 이상 상태를 빠르게 탐색. 숫자에 고정폭 글꼴 사용 | 긴 정책·구성 문서를 읽을 때 피로도 확인 필요 |
| [03 Ledger](03-ledger.html) | 중립적인 배경과 인디고, 문서형 운영 | 구성 변경·감사 기록에 적합한 절제된 선과 타이포그래피 | 상태 관제 화면의 중요도 구분을 더 강화할 수 있음 |

**권장: River.** 현재 기능이 이미 많으므로 장식 추가보다 일관된 정보 위계가 먼저다. 같은 상태 배지, 4개 핵심 지표, 예측 가능한 표와 검토 패널을 재사용하기 쉽다. Nightwatch는 별도 제품처럼 만들기보다 River의 다크 테마로 발전시키는 편이 유지보수에 유리하다. Ledger의 변경 검토 구조는 두 테마에 공통으로 가져갈 수 있다.

현재 화면의 실제 업무인 HTTP/TCP/UDP 라우트 관리, JWT·mTLS 진단, 인증서, 캐시·Docker, 구성 리비전 및 변경 이력을 반영했다. 아래 원칙으로 실제 적용 범위를 나누면 기능 회귀를 줄일 수 있다.

1. 공통 색상·간격·글꼴·배지 토큰과 주요 페이지 헤더부터 통일한다. 기존 DOM ID와 i18n 키를 유지한다.
2. 라우트 표의 핵심 정보는 ID, 매칭 순서, 호스트/경로, 업스트림, 접근 정책, 관측 상태로 유지한다. 편집 상세 정보는 별도 패널에 둔다.
3. 실시간 관측과 저장된 이력을 구분한다. 누적 카운터·관측 구간·리비전의 의미를 화면 가까이에 표시한다.
4. `—`와 `0`, 연결 해제와 오류, 변경 검증과 런타임 활성화 확인을 시각적으로 구별한다. 색상과 텍스트를 함께 사용한다.
5. 변경 전에 기준 리비전과 차이를 확인할 수 있게 한다. 충돌 또는 결과 불명 시 재읽기하는 현재 동작을 유지한다.

모바일에서는 사이드바를 가로 탐색으로, 지표를 2열로, 상세 패널을 1열로 바꾸며 표는 가로 스크롤한다. 키보드 포커스와 표 헤더 범위를 포함했다. 실제 제품 적용 시 접근성, 번역 길이, viewer 권한, 재접속·로그아웃 시 데이터 초기화 테스트를 유지해야 한다.

## 프런트엔드 보안 검토

검토 범위는 `web/app.js`, `console.js`, `operations.js`, `docker.js`, `i18n.js`와 관련 Playwright 테스트 및 `src/ui.rs`이다. 이 범위에서 재현 가능한 DOM XSS 취약점은 찾지 못했다. 이는 전체 제품의 안전성을 보증하는 결과는 아니다.

- 주요 스크립트에서 `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `eval`, `document.write` 싱크가 발견되지 않았다. 동적 API 문자열은 DOM 생성과 `textContent`로 표시한다.
- 경로·라우트 ID·사용자 ID·IP 등 API URL에 들어가는 외부 값은 확인한 경로에서 `encodeURIComponent`로 인코딩한다. 다운로드 링크는 로컬 Blob URL이다.
- `src/ui.rs`는 `default-src 'none'`, `script-src 'self'`, `connect-src 'self'`, `base-uri 'none'`, `frame-ancestors 'none'` 등을 포함하는 CSP를 제공한다.
- `api()`는 응답 수신 및 본문 해석 후 인증 세대를 다시 확인한다. 라이브 스트림도 세대를 확인해 로그아웃 뒤 늦은 응답이 화면을 복구하지 않도록 한다. SSE 프레임은 1 MiB 상한과 재연결 제한을 둔다.
- 계정 세션은 `sessionStorage`에 보관한다. 같은 출처 스크립트가 접근할 수 있으므로 XSS를 막는 현재 렌더링·CSP 규칙을 계속 유지해야 한다. 장기 관리자 토큰의 추가 브라우저 저장은 도입하지 않는 편이 좋다.
- 기존 테스트에 악성 HTML 형태의 사용자 이름·라우트 ID·HTTP 기록·TCP 기록·GeoIP·업스트림 주소·Lua 소스가 문자로 표시되는 검증이 있다.

초기 환경에는 Node가 없었으나, 체크섬 검증한 Node 24와 기존 Chromium으로 브라우저 검증을 추가했다. 실제 화면의 [밝은 테마](river-light.png), [어두운 테마](river-dark.png), [한국어 모바일](river-mobile.png) 스크린샷을 저장하고 직접 검토했다. 세 화면의 가로 넘침 검증을 포함한 3개 시각 확인 테스트가 통과했다. 핵심 버튼·보조 텍스트·선택 탐색 항목의 색상 대비 6종은 모두 4.5:1 이상이다. 배포된 서비스에 대한 침투 시도는 이 작업 범위에서 수행하지 않았다.

전체 fixture Playwright 검증은 최종적으로 **372개 통과, 17개 건너뜀, 실패 없음**이다. 건너뛴 항목은 별도의 실제 서버와 테스트 환경을 요구한다. 최초 실행은 동시 스크린샷 실행의 결과 폴더 충돌로 3개 아티팩트 기록 오류와 1개 일시적 폴링 실패가 발생했다. 해당 4개를 독립 재검증해 모두 통과한 뒤, 독립 출력 폴더에서 전체 테스트를 다시 실행해 위 최종 결과를 확인했다.
