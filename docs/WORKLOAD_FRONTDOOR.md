# Typed observed identity at the HTTP frontdoor

An observed Workload route uses its native configuration class to select Pumgye's additive `WorkloadResourceAuthorization.Decide` for the preliminary resource policy. That metadata query evaluates only `workload_users` in the same native compiler/View; existing Service and nonobserved Human/default routing retain their existing endpoints. Workload cannot fall back to an untyped local policy. Do not duplicate a Workload grant into `users` or skip the preliminary permission gate to reach final dispatch.

The generic authenticated native Verify still runs first. Before forwarding response headers, Root checks that the raw native result has exactly one principal kind matching the configured observed route class and valid AAL0. A tiny internal subject/AAL metadata tuple is retained for this preliminary query, independently of the origin response-header allowlist. Neither client-supplied identity headers nor provider response kind selects the endpoint. The tuple is not a receipt, opaque authentication capability, signed permission or revocation lease. Nonobserved Human/Service authentication and policy selection remain unchanged.

This ordering matters: the previous HTTP frontdoor used the legacy `users` query even for a Workload-only native route, so a legitimate `workload_users` grant could receive403 before the final Workload observed chain. The correction keeps the enforced policy before Lua. Final public SDK Workload authentication, dedicated signed native permit, consuming contract3/shared replay and raw under-TLS dispatch gates remain independently required. A preliminary Allow cannot replace any of them.

The actual HTTP Proxy regression uses authenticated fixture peers/public SDK, the actual core compiler, a real frontend/backend and production raw-gated outbound path. It verifies Workload-only rights choose the dedicated query, Service keeps legacy query, both work with kind omitted from forwarded headers, and point denial/wrong authenticated kind/nonzero AAL cause zero Lua-worker, SDK Issue, permit, output or backend effects. Immediately after public SDK Issue returns, the final opaque authentication must match the server-retained preliminary subject, fixed class, AAL0 and configured service/audience. A valid receipt for another principal is refused before permit/output/backend. Both principals are granted in the mismatch regression, so policy denial cannot hide this fence. This comparison cannot undo any Lua already run for the preliminary principal.

Fixed native output headers are reserved independently of the forwarding allowlist: subject, AAL, kind, service, evidence TTL and projected subject. Reservation follows the existing snapshot-wide union: configuring any observed route also strips client lookalikes on other routes in that snapshot. A snapshot without observed routes retains its previous namespace. Allowed forwarded identity values still come only from authenticated Verify; omitted kind remains absent at the backend.
