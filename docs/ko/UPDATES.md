# 서명된 업데이트

[문서 목차](../README.ko.md) · [한국어 안내](README.md) · [English](../UPDATES.md)

이 문서는 한국어 보조 요약입니다. 전체 설정과 동작 조건은 [영문 기준 문서](../UPDATES.md)를 확인하세요.

## 개요

Hangang 업데이트는 `--supervised`, `--update-manifest`, 운영자가 지정한
업데이트 키를 모두 설정했을 때만 실행되며, 해당 Ed25519 공개키로 서명된
매니페스트만 허용합니다. 내장 기본키나 무서명 우회 경로는 없습니다.
매니페스트는 버전, 빌드 대상, 아티팩트 URL, SHA-256, 정확한 크기를 모두
서명하며, 다운그레이드와 다른 빌드 대상은 거부합니다.

운영 환경에서는 HTTPS만 사용하고 리다이렉트의 출처 변경을 허용하지
않습니다. 다운로드는 128 MiB로 제한하고 임시 파일에 기록한 뒤 크기와
해시를 확인하고 fsync 합니다. 설치 시 기존 파일의 롤백 링크를 보관한 뒤
같은 디렉터리에서 원자적으로 교체합니다.

`--supervised` 모드에서는 상위 프로세스 PID를 유지한 채 공개/Admin/TCP
리스너를 새 자식 프로세스로 전달합니다. 새 프로세스가 설정과 리스너를
검증하고 READY를 보낸 뒤에만 이전 프로세스의 연결을 drain 합니다. READY
이전 실패 시 기존 실행 파일을 원자적으로 복구하고 이전 프로세스가 계속
서비스합니다. `/v1/update/status`와 `/v1/update/check`는 Admin bearer token이
필요합니다.

## 서비스 연속성과 배포 조건

감독 모드에서는 준비된 프로세스에 리스너를 인계하고 기존 연결은 이전
프로세스에서 처리합니다. 연결 종료 대기는 기본 30초이며 `--drain-seconds`로
조절합니다. 기한을 넘는 연결이나 철회된 보안 정책의 스트림은 종료될 수 있습니다.
설정 변경은 재시작 없이 적용하지만 저장 성공과 각 인스턴스의 적용 완료는
구분해야 합니다.

서명 업데이트의 자동 바이너리 롤백은 새 프로세스의 `READY` 이전 실패를
대상으로 하며 정상적인 파일시스템이 필요합니다. 수동 바이너리 교체 후 재시작은
실패한 파일을 자동 복구하지 않습니다. `READY` 이후 장애나 데이터베이스 스키마
변경도 자동으로 되돌리지 않습니다. 읽기 전용 Compose 템플릿은 컨테이너 교체
방식이므로 프로세스 인계에 의한 무중단 업그레이드가 자동 적용되지는 않습니다.

전체 조건은 [영문 배포 모드 안내](../UPDATES.md#continuity-and-deployment-modes),
재현 가능한 검사는 [수명 관리 검증](../UPDATES.md#verify-lifecycle-behavior)을
참고하세요.

[UDP/QUIC](../UDP.md)는 감독 모드를 거부하며 소켓·세션 인계를 지원하지 않습니다. UDP 라우트 변경이나 프로세스 교체는 해당 흐름을 초기화합니다. 별도 [DSR 도구](../DSR.md)도 게이트웨이 감독 프로세스의 인계 대상이 아닙니다.
