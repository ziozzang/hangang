# Linux IPVS 직접 라우팅

[문서 목차](../README.ko.md) · [English](../DSR.md)

`hangang-dsr`는 명시적으로 설계된 Linux 직접 라우팅 네트워크를 위한
독립 보조 프로그램입니다. 엄격한 JSON을 검증하고 목록에 지정한 IPVS
가상 서비스만 설치하거나 제거합니다. Hangang 라우트 설정, VIP 광고, 라우트·ARP
설정, 상태 점검과 장애 조정기는 제공하지 않습니다.

Linux IPVS(`/proc/net/ip_vs`)와 `ipvsadm`가 모두 필요하며, 둘 중 하나라도
없으면 안전하게 중단합니다.

[예제 설정](../../examples/dsr/config.json)은 IPv4 VIP·포트·프로토콜과 하나
이상의 IPv4 백엔드를 지정합니다. `tcp`와 `udp`를 지원하며 백엔드는 IPVS
직접 라우팅(`-g`)으로 등록합니다. 실제 네트워크에서 VIP 소유, ARP 억제와
직접 반환 경로를 별도로 구성해야 합니다. IP 패킷의 클라이언트 출발지와
VIP 목적지는 유지되므로, 백엔드가 올바르게 구성되면 클라이언트로 직접
응답할 수 있습니다.

`--check`는 IPVS를 변경하지 않고 소유 대상 계획만 출력합니다. `--apply`와
`--cleanup`은 설정에 지정된 VIP 서비스만 제거·생성하며 전역 `ipvsadm -C`를
호출하지 않습니다. `--apply`는 이미 존재하는 IPVS 서비스를 덮어쓰지 않으며,
일부 추가가 실패하면 해당 실행에서 새로 만든 서비스를 정리합니다. 알 수 없는 JSON 필드, 중복 서비스·백엔드, 안전하지
않은 스케줄러 문자열, 루프백·미지정 주소, 0 포트, 과도한 목록과 256KiB를
초과하는 파일은 거부합니다. 정리는 기존 스케줄러, 직접 라우팅 방식,
백엔드와 가중치가 JSON과 정확히 일치할 때만 수행합니다. 셸 문자열 보간은 사용하지 않습니다.

Docker 테스트는 보조 프로그램의 `--apply`와 `--cleanup`으로 TCP·UDP를
실행하고, 출발지 IP와 백엔드 Ethernet 소스 MAC을 확인합니다. IPVS 또는
Docker 네트워크가 노출되지 않으면 진단과 함께 실패합니다. 테스트는
호스트 네트워크, privileged 컨테이너, 호스트 sysctl과 운영 리소스를 사용하지
않습니다. ARP, 다중 호스트 라우팅, 엔드포인트 세대 제어, drain, IPv6,
성능과 운영 네트워크에서의 추가 UDP 시나리오는 별도로 검증해야 합니다.

`make test-dsr`로 설정 검증, 보조 프로그램 빌드, 격리된 Docker 검증을 실행합니다. 동일 서비스 설정을 여러 작성자가 동시에 변경하지 않도록 직렬화해야 합니다. 검증된 브리지 토폴로지 이외의 다중 호스트·클라우드 네트워크는 별도로 검증해야 합니다.
