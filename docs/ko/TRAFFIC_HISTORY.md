# 최근 트래픽 메타데이터

[Documentation](../README.ko.md) · [English](../TRAFFIC_HISTORY.md)

Hangang은 관리 콘솔을 위해 끝난 HTTP **응답 헤드** 기록을 프로세스 안의 링(ring)에 보관합니다. 최대 4096개를 보관하며 60초보다 오래되지 않은 기록만 보여 줍니다. 용량 때문에 보이는 기간이 더 짧아질 수 있습니다. 초당 약 100건이면 41초, 초당 1000건이면 약 4초 만에 가득 찹니다. 오래된 항목은 다음 기록이나 조회 때 정리되므로 한가한 프로세스는 그때까지 만료된 항목을 물리적으로 들고 있을 수 있지만, API는 만료된 기록을 돌려주지 않습니다. 이 링은 영구 접근 로그나 패킷 캡처가 아닙니다.

각 기록에는 시각, 실제 소켓 상대 IP와 출발 포트, 실제 클라이언트 IP, HTTP 메서드, 쿼리 문자열을 뺀 경로, 고른 라우트 ID(있을 때), 응답 상태, 응답 헤더까지 걸린 시간, 프로토콜과 TLS 여부가 들어갑니다. 실제 클라이언트 IP는 소켓 상대가 설정한 신뢰 프록시 CIDR 안일 때만 전달 헤더에서 가져오고, 그렇지 않으면 소켓 상대와 같습니다. 고른 라우트 ID는 나중에 TLS·IP·인증·정책 검사에서 거부된 요청에도 나타날 수 있습니다. 응답 헤드 시간에는 본문 스트리밍이나 업그레이드된 터널의 수명이 들어가지 않습니다. 상태 검사 요청은 빠지고, 거부된 데이터 경로 요청은 들어갑니다. 문자열은 길이가 제한되며 출력할 수 없는 바이트는 바뀝니다. 헤더, 인가 값, 쿠키, 요청·응답 본문, 쿼리 문자열은 이 링에 복사하지 않습니다. 다만 **경로 조각** 안에 넣은 비밀은 관리자만 보는 경로 필드에 나타날 수 있으므로, 애플리케이션은 URL 경로에 자격 증명을 넣지 말아야 합니다.

관리자 계정과 시스템 관리자 토큰만 `GET /v1/traffic`을 읽거나 `/v1/events`에서 `event: traffic`을 받을 수 있습니다. 조회 전용(viewer) 세션은 클라이언트 IP 이력 없이 상태 이벤트만 받습니다. 이력 조회는 선택적인 `after` 커서와 128 이하의 `limit`을 받습니다. 커서와 현재 링 사이의 기록이 밀려났거나 커서가 다른 세대의 것이면 응답에 `gap`이 들어가고, `dropped_total`은 나이·용량 때문에 밀려난 수를 세며, `server_time_unix_ms`로 브라우저가 자기 시계를 믿지 않고 남은 보관 시간을 계산할 수 있습니다. SSE 스트림은 약 1초마다 최대 128개를 보내므로 초당 128건을 넘는 요청이 이어지면 링에 새 기록이 있어도 `gap`이 생길 수 있습니다. 대시보드의 속도 그래프는 상태별 누적 카운터를 써야 하며, 최근 요청 기록은 활동을 보여 줄 뿐 많은 요청의 완전한 감사 기록이 아닙니다.

원시 TCP 연결은 생명주기 결과와 애플리케이션 바이트 수를 담은 별도의 [활성·최근 연결 이력](../TCP_CONNECTION_HISTORY.md)을 씁니다.

리비전이 있는 [HTTP 기록 정책](../HTTP_RECORDING.md)은 고른 응답 헤드를 이 링과 켜진 접근 추적에서 일부러 뺄 수 있습니다. 각 행은 그 결정을 내린 구성의 `policy_revision`을 담고, 묶음은 밀려난 수와 따로 누적 `filtered_total`을 보여 줍니다. 새 이벤트가 모두 빠져도 빈 SSE 트래픽 프레임이 이 카운터를 갱신합니다. 이 선택적 이력을 완전한 감사 기록으로 다루면 안 됩니다.

## 요청 상관 필드

각 기록과 `hangang::access` 로그 줄(`--access-log`로 켬)에는 상관 필드 다섯 개가 더 들어갑니다. `GET /v1/traffic` JSON에서는 다음과 같습니다.

| 필드 | 값 |
| --- | --- |
| `request_id` | 신뢰 프록시가 보낸 `x-request-id` 하나가 `A-Z a-z 0-9 - _ . : + / =` 문자 1–128개이면 그 값, 아니면 Hangang이 만든 16진수 32자입니다. 기록만 하고 업스트림 요청에 넣지는 않습니다. |
| `trace_id` | 업스트림과 외부 인가 서비스에 보낸 `traceparent`의 W3C 추적 ID(16진수 32자)입니다. 추적 문맥을 정하기 전에 거부된 요청은 `null`입니다. |
| `backend_index` | 라우트 `backends` 배열에서 고른 백엔드의 위치입니다. 캐시 적중, 게이트웨이가 만든 응답, 백엔드에 닿지 않은 요청은 `null`입니다. |
| `backend_id` | 그 백엔드의 이름 있는 멤버 ID입니다. 주소만 적은 백엔드는 `null`입니다. |
| `response_bytes` | 응답 헤드 시점에 선언된 본문 길이입니다. `Content-Length`이거나, `HEAD`·1xx·204·304는 `0`입니다. 길이 없이 스트리밍하는 본문과, 설정한 오류 페이지가 본문을 바꿀 수 있는 게이트웨이 생성 응답은 `null`입니다. |

문자열 필드는 128자 제한을 지키고 출력할 수 없는 바이트를 바꿉니다. 텍스트 접근 로그에서는 값이 없으면 `-`로 씁니다.

추적 문맥은 클라이언트 주소와 같은 신뢰 규칙을 따릅니다. 신뢰 프록시 CIDR 안의 상대가 보낸 올바른 버전 00 `traceparent` 하나는 `tracestate`와 함께 그대로 넘깁니다. `traceparent`가 없거나, 여러 개이거나, 형식이 틀리거나, 신뢰하지 않는 상대가 보낸 것이면 새로 만든 표본 제외(unsampled) 값(`00-<무작위 추적>-<무작위 부모>-00`)으로 바꾸고 예전 `tracestate`는 지웁니다. 받아들이는 값은 소문자 16진수여야 하며 다른 버전은 형식 오류로 봅니다. Hangang은 스팬(span)을 내보내지 않습니다. 추적 ID는 Hangang 기록을 업스트림·인가 서비스 로그와 잇는 데만 씁니다.
