# Request parameter blocks

[Documentation](../README.ko.md) · [English](../REQUEST_BLOCKS.md)

관리자 보안 설정 메뉴에서 `settings.request_blocks`를 JSON으로 편집합니다. 일반적인 파라미터 패턴 정책이며 인증 서비스·캐시·Lua·원본 서버 전에 선택한 요청을 차단합니다. 규칙 안의 조건은 AND, 일치하는 규칙은 OR입니다. 빈 설정은 요청을 변경하지 않습니다. 기존 리비전 확인 설정 게시 흐름으로 적용하며 새 API·제품 레지스트리·쿠키 자동 예외·인증 우회를 추가하지 않습니다.

## Configuration

```json
{
  "settings": {
    "request_blocks": [{
      "path": "/control",
      "hosts": ["app.example.test"],
      "include_subpaths": false,
      "methods": [],
      "params": [{"name": "action", "values": ["delete"], "match": "exact"}],
      "max_body_bytes": 65536,
      "timeout_ms": 2000
    }]
  }
}
```

경로는 기존 정규 절대 경로 규칙을 사용하며 하위 경로는 `include_subpaths:true`로 선택합니다. 빈 `hosts`는 모든 호스트이며 기존 호스트 이름·IP 패턴을 최대 16개 허용합니다. 빈 `methods`는 모든 메서드이고 명시적 목록은 중복 없는 GET·HEAD·POST·PUT·PATCH·DELETE·OPTIONS·TRACE를 최대 8개 허용합니다. 최대 128개 규칙과 전체 정책 텍스트 32 KiB를 허용합니다. 규칙마다 조건은 1–16개이며 이름은 고유한 정규 ASCII 영문자·숫자·밑줄·하이픈 1–64자입니다. 조건마다 중복 없는 값을 최대 128개, 값당 최대 4,096 UTF-8바이트로 지정합니다.

## Conditions

빈 `values`는 실제 존재 여부를 검사합니다. `match` 기본값은 `exact`입니다. `prefix`는 리터럴 접두사, `segment_prefix`는 정확한 일치나 슬래시로 구분한 하위 값을 검사합니다. `path_prefix`는 파라미터 경로도 정규화하며 맨 앞 슬래시 생략을 허용합니다. `case_insensitive` 기본값은 false이고 ASCII 대소문자를 비교합니다. 선택적 `strip_pattern`은 최대 256바이트의 Rust 정규식이며 컴파일 자원을 제한합니다. 비교값만 변경하며 전달하는 요청은 변경하지 않습니다.

`negate:true`는 값이 없거나 추출한 값 중 하나라도 일치하지 않으면 적용합니다. `default_value`는 파라미터가 완전히 없음을 확인한 뒤 비교용 값으로만 사용합니다. 비어 있지 않은 `values`와 생략한 `json_field`를 요구하며 최대 4,096바이트입니다. 전달할 파라미터를 삽입하지 않습니다. 따라서 부정 조건을 적용한 읽기 전용 허용 목록으로 알려진 읽기를 허용하고 향후 추가될 변경 명령을 포함한 알 수 없는 명령을 차단할 수 있습니다.

`json_field`는 파라미터의 JSON 객체·배열·인코딩된 JSON 문자열에서 이름이 일치하는 스칼라 말단 값을 재귀적으로 추출합니다. 깊이 16, 노드 1,024개, 디코딩한 문자열 16 KiB로 제한합니다. 잘못된 JSON과 JSON 객체의 중복 키는 관련 없는 키를 포함하여 거부합니다. 일반적인 추출이며 특정 애플리케이션 전용 파서가 아닙니다.

## Parsing and resource limits

선택한 요청의 쿼리 파라미터·URL 인코딩 폼·multipart 폼·최상위 JSON 파라미터를 검사합니다. multipart는 원본 서버로 전달하기 전에 전체 검사하여 뒤에 오는 제어 필드도 검사합니다. 보호 이름의 퍼센트 인코딩은 디코딩하며, 모호한 PHP 스타일 별칭이나 중복 보호 이름은 거부합니다. 관련 없는 대괄호 이름과 중복은 유지합니다. 보호 범위에서는 메서드 재정의 헤더·필드를 거부합니다. 허용한 요청의 원래 바이트와 헤더는 보존합니다.

쿼리는 최대 16 KiB·256쌍, URL 인코딩 폼은 256쌍, multipart는 256개 부분·부분 헤더 4 KiB·경계 문자열 70바이트로 제한합니다. JSON 파싱은 깊이 16·노드 1,024개이며 보호 스칼라 값은 4,096바이트로 제한하고 제어 문자를 거부합니다. 본문 검사는 동시 실행 슬롯 4개이며 빈 본문·쿼리 전용 요청은 슬롯을 소비하지 않습니다. 기본 본문 제한은 64 KiB, 시간 제한은 2초이며 명시적으로 1–16,777,216바이트와 1–5,000밀리초를 지정할 수 있습니다. 최종 차단 조건이 일치하지 않아도 선택한 업로드 엔드포인트에 제한을 적용합니다. 넓은 호스트·경로 규칙을 활성화하기 전에 정상적인 대용량 업로드를 고려하세요. 범위 밖 업로드는 영향을 받지 않습니다. 조건 일치는 403, 잘못되거나 모호한 입력은 400, 지원하지 않는 형식·인코딩은 415, 크기 초과는 413, 시간 초과는 408, 검사 용량 소진은 503입니다. 응답에 파라미터 값을 노출하지 않습니다.


## Multipart disk inspection

업로드에 적용될 수 있는 범위의 모든 요청 차단 규칙에 `multipart_spool`을 추가하세요. RAM 제한을 초과하는 알려진 크기의 multipart 본문과 크기가 알려지지 않은 청크 multipart 본문은 비공개 디스크 검사로 처리합니다. 범위의 규칙 중 하나라도 명시하지 않으면 기존 RAM 제한을 유지합니다. 일치하는 규칙은 설정한 제한 중 최솟값을 사용합니다. JSON과 URL 인코딩 폼은 기존 제한을 유지하며 빈 본문과 범위 밖 업로드도 유지합니다.

```json
{
  "multipart_spool": {
    "directory": "/data/request-inspection-spool",
    "max_body_bytes": 68719476736,
    "timeout_ms": 7200000,
    "idle_timeout_ms": 60000,
    "max_field_bytes": 65536
  }
}
```

쓰기 가능한 비공개 마운트에 디렉터리를 미리 생성하고 권한 0700·게이트웨이 프로세스 UID 소유로 설정하세요. 절대 경로는 최대 2,048바이트이며 경로 탐색과 심볼릭 링크 구성 요소를 허용하지 않습니다. 서버가 파일 시스템 디스크립터를 검증합니다. 게이트웨이는 익명 0600 파일을 사용하며 전체 multipart 문법과 보호 제어 필드 검사를 통과하기 전에는 업로드 바이트를 전달하지 않습니다. 허용한 업로드는 요청되는 만큼 원래 바이트로 재생합니다. 바이너리 파일 부분은 보존하며 애플리케이션 콘텐츠를 스캔하지 않습니다. 텍스트 제어 필드는 `max_field_bytes`로 제한합니다.

디스크 본문 최대 크기는 64 GiB입니다. 전체 시간 제한 기본값은 1시간, 최댓값은 2시간이며 예시는 2시간을 명시적으로 선택합니다. 유휴 시간은 기본 60초·최대 120초이고 텍스트 필드는 기본·최대 64 KiB입니다. 공유 검사 슬롯 2개와 전체 디스크 할당량 128 GiB의 소유권은 재생이나 바이트 참조가 살아 있는 동안 유지합니다. 크기 초과는 413, 전체·유휴 시간 초과는 408, 할당량·입출력 실패는 503, 잘못된 multipart는 400입니다. 공통 RAM·디스크 파서는 모호한 경계와 bare-LF 문법을 거부하며 느슨한 PHP 방식으로 재해석하지 않습니다. 게시 전에 용량과 마운트 권한을 설정하세요. 지원하지 않는 디렉터리는 검증에서 거부합니다.

## Application examples

[WordPress·Mangboard 설정](../../examples/security/request-blocks/wordpress.json)과 [DSM 설정](../../examples/security/request-blocks/dsm.json)은 도메인 자리 표시자를 쓰는 명시적인 운영자 예시이며 핵심 제품 동작이 아닙니다. 기존 설정에 배열을 병합하고 실제 파라미터 이름과 사용 흐름을 검토한 뒤 게시하세요. WordPress 예시는 XML-RPC 경로·사용자 REST 별칭·작성자 열거를 차단하고, 위험 동작·사용자 모드 조건과 읽기 전용 명령 허용 목록을 보여 줍니다. 넓은 프로필은 JSON·폼 16 MiB·5초 제한과 multipart 디스크 검사 64 GiB·2시간을 명시적으로 선택합니다. 선택한 관리자 제어는 로그인 쿠키와 관계없이 적용합니다.

DSM 예시는 `SYNO.Auth.ForgotPwd`를 직접 차단하거나 `compound`·`params`의 JSON 필드를 통해 차단합니다. 알려진 CGI 별칭은 명시적인 [경로 차단](PATH_BLOCKS.md)으로도 예약합니다. 선택한 비밀번호 재설정 작업을 모든 일치 요청에서 의도적으로 차단합니다. 예시는 임의의 외부 연동이나 쿠키 기반 권한을 가정하여 보존하지 않습니다. 배포한 애플리케이션에서 필요한 로그인·목록·검색·읽기 흐름을 검증하세요.


디스크 검사는 Linux와 선택한 파일시스템의 익명 `O_TMPFILE` 지원이 필요합니다. Linux 이외의 빌드는 `multipart_spool` 설정을 거부하며, 이름이 있는 임시 파일로 대체하지 않습니다. 기존의 제한된 메모리 검사는 Linux와 macOS에서 계속 사용할 수 있습니다.

설정한 요청 본문 변환은 그대로 적용됩니다. 변환된 본문은 최초 유입 요청의 정책 범위에서 다시 검사하며, 이전 디스크 파일에 저장된 제어 값으로 검사를 대체하지 않습니다. 스트리밍 변환이 원본을 유지하는 동안에는 추가 디스크 검사 슬롯이 필요할 수 있고, 용량 부족 시 503으로 거부합니다.

디렉터리 권한·소유권·심볼릭 링크는 설정 검증에서 확인합니다. Linux 익명 파일 생성 기능을 지원하지 않는 파일시스템은 실제 검사 시 503으로 거부합니다.
