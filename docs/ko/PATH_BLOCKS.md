# URL security controls

[Documentation](../README.ko.md) · [English](../PATH_BLOCKS.md)

관리자 Settings 메뉴에서 URL 차단, 국가·IP 허용 목록, 요청 속도 제한, 실패 누적에 따른 IP 차단과 선택적인 공유 Redis를 설정할 수 있습니다. 이 제어는 일반 라우트 매칭 조건과 독립적으로 동작하며, 인증 서비스·캐시·Lua·업스트림에 접근하기 전에 적용됩니다. 기본값은 빈 목록이며, 이미지를 포함해 설정하지 않은 URL에는 요청 속도 제한을 적용하지 않습니다. 전체 JSON 편집기 또는 리비전 조건을 검사하는 구성 API로 설정을 게시합니다. 새 요청은 게시된 스냅샷을 사용하며, 이미 허용한 응답을 소급해 취소하지 않습니다.

## Configuration

```json
{
  "settings": {
    "path_blocks": [{"path": "/.git"}, {"path": "/.env"}],
    "path_allowlists": [{"path": "/office/login", "hosts": ["app.example"], "allow_cidrs": ["192.0.2.0/24"]}],
    "path_rate_limits": [{
      "path": "/login", "hosts": ["app.example"], "tps": 5, "burst": 10,
      "limits": [{"requests": 100, "window_seconds": 60}, {"requests": 1000, "window_seconds": 86400}]
    }],
    "path_failure_bans": [{
      "path": "/login", "hosts": ["app.example"], "failures": 5,
      "window_seconds": 300, "ban_seconds": 900, "statuses": [401, 403]
    }],
    "failure_ban_scope": "url"
  }
}
```

국가만으로 접근을 제한하려면 허용 목록 규칙을 `{"path":"/login","hosts":["app.example"],"allow_countries":["KR"]}`로 바꾸고 기존 [GeoIP 소스(영문)](../GEOIP.md)를 준비합니다. `allow_cidrs`와 `allow_countries`가 모두 있으면 두 조건을 모두 통과해야 합니다. 여러 규칙이 겹치는 경우에도 모든 규칙을 만족해야 합니다. 국가를 알 수 없으면 `403`으로 거부하며, 데이터베이스를 사용할 수 없거나 만료되면 허용하지 않고 `503`을 반환합니다. 국가는 IP 메타데이터이며 인증된 신원이 아닙니다. 데이터베이스에서 한 번 관측해 복사한 결과를 이후의 라우트·Lua 정책과 공유합니다.

## Path and host matching

`path_blocks`는 디렉터리 자체와 슬래시로 구분되는 하위 경로를 일치시킵니다. `/private`와 `/private/file`은 `404`로 차단하지만 `/private-news`는 별도 경로입니다. `/`는 모든 애플리케이션 경로를 차단합니다. `/.env.bak` 같은 파일에는 별도 규칙이 필요하며, 암묵적인 접미사 또는 정규식 매칭은 없습니다.

다른 URL 제어는 기본적으로 정확한 경로만 일치시킵니다. `/login`은 `/login/image.png`를 포함하지 않으며, 하위 경로까지 적용하려면 `include_subpaths: true`를 명시합니다. `hosts`를 생략하거나 빈 목록으로 설정하면 모든 호스트·리스너에 적용합니다. 호스트 패턴에는 일반적인, 크기가 제한된 호스트 이름 glob을 사용합니다. 외부에 노출한 모든 별칭을 포함하거나, 게이트웨이 전체에 적용할 경로라면 호스트를 생략합니다. 신뢰하는 전달 호스트와 절대 URI의 authority도 매칭에 참여합니다. 클라이언트가 보낸 전달 헤더만으로 다른 IP를 선택할 수는 없습니다.

경로는 대소문자를 구분하는 정규 절대 경로이며 최대 2048바이트입니다. 이스케이프와 끝 슬래시는 허용하지 않으며 루트 `/`만 예외입니다. 쿼리는 매칭에 영향을 주지 않습니다. 적용 대상 호스트의 요청 경로는 이스케이프를 한 번만 디코딩합니다. 인코딩된 구분자, 이중 인코딩, 경로 순회, 반복 슬래시, 역슬래시, 세미콜론 매개변수, 잘못된 UTF-8과 제어 문자는 `400`으로 거부합니다. 엄격한 매칭은 애플리케이션이 사용하는 특정 인코딩도 거부할 수 있으므로 적용 범위를 신중하게 지정하세요. 전용 상태 확인 요청은 URL 차단·속도 제한·허용 목록을 우회하지만, 명시적인 호스트·전역 IP 차단은 상태 확인 응답보다 먼저 적용됩니다. 별도 관리자 복구 경로에는 이 공개 HTTP 제어를 적용하지 않습니다. 이 기능은 OS 방화벽 규칙을 설치하거나 원시 TCP·UDP의 접속 허용을 변경하지 않습니다.

## Simultaneous rate limits

`tps`는 선택적인 지속 토큰 보충 속도이며, `burst`는 즉시 사용할 수 있는 최대 토큰 수입니다. `burst` 기본값은 1입니다. `limits`에는 고정 구간 카운터를 최대 8개 추가할 수 있습니다. 60초는 분, 3600초는 시간, 86400초는 일 단위입니다. TPS 또는 비어 있지 않은 `limits` 배열 중 하나 이상이 필요합니다. 모든 구간에서 요청을 허용해야 통과합니다. TPS·burst·구간별 요청 수는 1–1000000, 구간 길이는 1–86400초를 허용합니다.

각 규칙의 예산은 클라이언트·메서드·연결·리스너 사이에서 공유합니다. 토큰과 카운터는 요청을 허용할 때 차감하며, 취소·인증 실패·업스트림 오류 뒤에도 돌려주지 않습니다. 거부 응답은 상세 원인을 노출하지 않는 `429`이며 `Retry-After: 1`과 `Cache-Control: no-store`를 포함합니다. 동일한 규칙은 관련 없는 구성 변경 뒤에도 로컬 상태를 유지합니다. 규칙 수정·제거·재시작은 로컬 상태를 초기화합니다. 로컬 규칙 하나에서는 모든 구간을 검사한 뒤 차감하지만, 로컬 규칙 여러 개가 겹치면 앞선 규칙의 예산을 소비한 뒤 나중 규칙에서 거부할 수 있습니다. 공유 Redis는 선택한 모든 규칙·구간을 원자적으로 검사한 뒤 차감합니다.

로컬 고정 구간은 버킷 생성·초기화 시 시작하며 단조 시간을 사용합니다. Redis 구간은 서버의 UTC·Unix epoch 경계에 맞추므로 일일 할당량은 UTC 자정에 초기화됩니다. 고정 구간은 경계 전후에 요청이 몰리는 것을 허용할 수 있으며, 이동하는 최근 24시간의 합계가 아닙니다. TPS는 계속해서 일정한 속도로 토큰을 보충하는 버킷입니다. 기존 연결·TLS·본문 작업 제한은 URL 요청 허용 이전의 작업을 보호합니다.

## Failure bans and management

실패는 설정한 URL에서 실패 관측을 허용한 뒤에만 집계합니다. 설정한 상태 코드에는 게이트웨이 정책·속도 제한의 거부, 인증 응답 또는 업스트림 응답을 포함할 수 있습니다. 잘못된 매칭 값으로 인해 관측 이전에 거부한 요청은 집계하지 않습니다. 기본값인 401·403은 일시적인 503 오류를 제외합니다. 집계 구간은 처음 집계한 응답 실패에서 시작하며, 성공이 누적 실패를 지우지 않습니다. 임계값에 도달하면 고정 기간의 차단을 설정합니다. 이미 허용한 응답은 차단을 연장하거나, 자연 만료·관리자 해제 뒤에 다시 만들 수 없습니다. 취소는 실패로 집계하지 않습니다.

`failure_ban_scope` 기본값은 `url`입니다. `host`는 발생한 차단을 해당 규칙의 호스트에 있는 모든 경로로 확장하며, 빈 `hosts`는 모든 호스트를 뜻합니다. `global`은 설정한 URL에서 발생한 IP 차단을 이미지와 상태 확인 경로를 포함한 모든 공개·워크로드 HTTP 호스트·경로로 확장합니다. 검증한 클라이언트 IP를 사용하며, 설정한 신뢰 프록시가 이 IP를 전달할 수 있습니다. 별도 관리자 소켓·리스너에는 계속 접근할 수 있습니다.

관리자 메뉴에서 활성 차단을 조회하고, 정규 IPv4·IPv6 주소로 검색하며, 확인 후 해당 IP의 차단을 해제할 수 있습니다. API는 `GET /v1/security/bans?ip=...`와 `{"ip":"192.0.2.10"}` 본문을 받는 `POST /v1/security/bans/release`입니다. 조회는 최대 200건과 목록 잘림 여부를 반환합니다. IP로 검색하면 필터 없는 목록의 한도를 넘어선 IP도 조회할 수 있습니다. viewer는 차단 정보를 읽거나 해제할 수 없습니다. 해제는 활성 구성 규칙의 실패·차단 기록을 제거합니다. 이미 허용한 해제 작업은 호출자가 취소하거나 로그아웃한 뒤에도 완료할 수 있지만, 권한을 철회한 행위자는 새 작업을 허용받을 수 없습니다. 이전 관측은 새로 허용한 세대에 영향을 주지 못하도록 차단합니다.

각 규칙은 대기 중인 관측을 포함해 클라이언트 기록을 최대 1024개 추적합니다. 새 IP를 받기 위해 활성 차단을 퇴출하지 않습니다. 알려지지 않은 IP를 위한 용량이 없으면 허용하지 않고 `503`을 반환합니다. 로컬 취소는 예약을 해제합니다. Redis에서 중단된 예약은 제한된 TTL 뒤에 만료됩니다. 만료된 선택 실패 콜백은 기록을 다시 만드는 대신 허용하지 않고 `503`을 반환합니다. 규칙은 최대 128개, 규칙당 호스트는 최대 16개이며 목록별 매칭 조건·정책 텍스트 합계는 32KiB입니다. IP 허용 목록은 CIDR 최대 1024개, 국가 목록은 코드 최대 256개로 제한합니다. 잘못된 설정은 활성 문서를 변경하지 않습니다.

## Shared Redis and Valkey

```json
{
  "settings": {
    "security_redis": {
      "url_env": "HANGANG_SECURITY_REDIS_URL",
      "namespace": "hangang-security"
    }
  }
}
```

모든 게이트웨이에 해당 환경 변수를 Redis URL과 자격 증명으로 설정합니다. 구성과 UI에는 환경 변수 참조와 네임스페이스만 포함하며 URL·비밀번호를 넣지 않습니다. 기본 연결은 인증서를 검증하는 `rediss://` TLS 또는 루프백 평문 연결을 요구합니다. 운영자가 승인한 사설망 평문 서버에는 `allow_insecure_remote: true`를 명시해야 합니다. `#insecure`와 Unix URL은 거부합니다. 이 백엔드는 공개 TLS 신뢰 루트를 사용하며, 구성 저장소 백엔드의 사용자 지정 CA 옵션은 여기에 자동으로 적용되지 않습니다. 이 보안 백엔드는 현재 사용자 지정 CA를 지원하지 않습니다.

모든 노드는 같은 Redis 엔드포인트·데이터베이스·네임스페이스와 정규화한 규칙을 사용해야 합니다. Lua는 Redis TIME과 원자적인 다중 규칙 카운터를 사용합니다. 무작위 기록 epoch는 해제·재생성 뒤에 이전 콜백이 영향을 주지 못하게 합니다. 안정적인 구성 해시는 게이트웨이 재시작과 관련 없는 구성 게시 뒤에도 Redis 상태를 유지합니다. 키 hash tag는 스크립트 키를 같은 그룹에 넣습니다. 연결 관리는 단독 Redis·Valkey 또는 호환 프록시를 대상으로 하며, 네이티브 Redis Cluster 검색은 지원하지 않습니다.

보안 네임스페이스를 퇴출과 다른 애플리케이션의 쓰기로부터 보호하세요. 재시작 뒤에도 상태를 유지하려면 적절한 영속성·복제를 사용해야 합니다. Redis 데이터가 유실되거나 퇴출되면 예산과 차단도 사라집니다. 작업 제한 시간은 1초이며 동시 명령은 64개입니다. 장애가 발생하면 선택한 요청을 허용하지 않고 `503`으로 거부하며 로컬 상태로 대체하지 않습니다. 선택하지 않은 URL에는 영향을 주지 않지만, 호스트·전역 차단 범위가 공유 검사까지 명시적으로 요구하면 예외입니다. 관리자 복구는 독립적이지만 공유 상태의 조회·해제에는 백엔드가 필요합니다. UI는 로컬 상태와 공유 상태를 구분해 표시합니다. Redis가 없으면 각 노드가 별도 예산을 가지므로 전체 인스턴스에 걸친 공통 상한으로 간주해서는 안 됩니다.

## Private security logs

구조화한 비공개 이벤트에는 경로·허용 목록 거부, 속도 제한 거부, 선택한 실패, 차단 생성·거부, 백엔드 실패와 관리자 해제를 포함합니다. 검증한 클라이언트 IP와 상태 코드를 기록하며, 새로 생성한 차단에는 설정한 경로를 포함합니다. 이 기능은 원본 요청 URL·쿼리 문자열·본문·비밀번호·토큰을 기록하지 않습니다. 공개 응답은 상세 원인을 계속 노출하지 않습니다.

보안 이벤트는 프로세스당 초당 최대 10건입니다. 억제한 건수는 이후 출력한 이벤트에 함께 기록하므로 반복적으로 거부한 요청이 무제한 보안 로그를 만들지 못합니다. 기존 트래픽·접근 로그에는 별도의 정책과 보존 제어가 적용됩니다.

관리자 해제 이벤트는 요청 보안 이벤트와 별도의 초당 10개 예산을 사용하므로 공개 공격 트래픽이 관리자 로그 예산을 소모하지 못합니다. 해제 작업의 소유 worker가 실제 결과를 기록하므로 호출자가 연결을 끊어도 승인된 해제 작업은 로그에 남습니다.

로그 출력은 전용 worker 하나와 유한 큐(요청 이벤트 224개, 관리자 예약 이벤트 32개)를 사용합니다. 요청 처리 worker는 막힌 로그 저장소를 기다리지 않으며, 큐 초과도 생략 건수에 합산합니다.

정확한 URL 규칙에서도 요청 끝의 선택적 슬래시 하나는 같은 URL로 취급합니다. `/login`과 `/login/`으로 로그인 처리 한도나 허용 목록을 우회하지 못하며 `/login/image.png`에는 하위 경로 옵션을 명시하지 않는 한 적용하지 않습니다.
