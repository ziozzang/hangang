# Kubernetes 연동

이 문서는 한국어 보조 요약입니다. 전체 설정과 동작 조건은 [영문 기준 문서](../KUBERNETES.md)를 확인하세요.

## 개요

`--kubernetes-controller`는 Service와 `networking.k8s.io/v1` Ingress를 지속적으로 list/watch하여 검증된 전체 스냅샷만 실행 중 프록시에 반영합니다. API 장애나 잘못된 응답에서는 마지막 정상 설정을 유지하고, `410 Gone`이면 전체 목록을 다시 읽습니다. 서비스 계정 CA와 회전 토큰 파일은 새 요청마다 다시 확인합니다.

`--kubernetes-tls`를 사용하면 Ingress가 참조한 `kubernetes.io/tls` Secret으로 SNI 인증서 맵을 구성합니다. 인증서 발급은 외부 발급기가 담당합니다. Secret이 삭제되면 이를 참조하는 Ingress도 즉시 제외됩니다. `--kubernetes-publish-address`는 설정 반영에 성공한 뒤에만 resourceVersion 조건부 status patch를 수행하며, `409 Conflict`는 전체 relist 없이 해당 객체만 다시 읽어 재시도합니다.

호스트 이름은 네임스페이스 단위로 소유됩니다. 규칙 호스트, TLS 호스트, 호스트 없는 규칙과 기본 백엔드(`*`)는 해당 패턴을 요청하는 **가장 오래된 Ingress**(`metadata.creationTimestamp`, 동일하면 `metadata.uid`)의 네임스페이스가 소유하므로, 이벤트를 관찰한 순서가 달라도 모든 복제본이 같은 객체 집합에서 같은 결정을 내립니다. 다른 네임스페이스의 동일 호스트(또는 정확 호스트와 이를 덮는 와일드카드) 요청은 경고와 함께 해당 Ingress 전체가 제외되고 더 오래된 소유자는 밀려나지 않습니다. Ingress를 삭제 후 재생성하면 생성 시각이 갱신되어 그 사이 같은 호스트를 요청한 객체가 우선하므로, 팀 간 격리가 필요하면 어드미션 정책으로 호스트 유일성을 강제하십시오. 라우트는 정확 호스트, 와일드카드 호스트, 호스트 없음 순으로 먼저 정렬됩니다.

각 리소스 종류의 신선도를 추적합니다. list(종류별로 스냅샷 resourceVersion을 받은 시점 기준)·watch 이벤트·bookmark·정상 종료된 watch가 `--kubernetes-stale-seconds`(기본 60초) 이상 없거나 캐시가 용량 초과로 불완전하면 복제본은 준비되지 않음(readiness 503)을 보고하되 마지막 정상 스냅샷은 계속 서비스합니다. watch 요청이 수락된 것(200 응답 헤더)만으로는 신선도를 갱신하지 않으며, list나 스냅샷 생성이 진행 중인 동안에도 기한을 검사하므로 API 서버에서 멈춘 relist가 readiness를 붙잡아 두지 못합니다. 전체 relist는 결과와 무관하게 5초에 한 번만 시작되며 모든 재시도 지연에 ±20 % 지터가 적용됩니다. status 주소는 기존 목록에 병합되어 다른 복제본이나 컨트롤러의 항목을 지우지 않으며, 스냅샷에 포함된 Ingress만 주소를 받고 제외된 Ingress는 주소를 잃습니다. status 패치는 백그라운드 큐(동시 4개)에서 처리되어 게시를 지연시키지 않고, 큐는 게시 때마다 캐시와 맞춰져 삭제되었거나 클래스를 벗어난 객체의 작업은 버려지므로 생성·삭제가 반복되어도 캐시보다 커지지 않습니다. `409 Conflict` 후 다시 읽은 객체의 uid·generation·클래스가 큐에 넣을 때와 다르면(같은 이름으로 재생성, spec 변경, 클래스 이동) 그 작업은 적용하지 않고 버리며 다음 조정에서 다시 결정합니다. 사라진 복제본의 주소는 어떤 복제본도 지우지 않으므로 status에 영구히 남습니다. 복제본마다 다른 주소 대신 앞단 Service/로드밸런서의 주소 하나를 공유해 게시하고, 퇴역한 주소는 [영문 문서](../KUBERNETES.md)의 `kubectl patch --subresource=status` 절차로 한 번 제거하십시오. 생성 설정은 1,024 라우트와 1 MiB로 제한되며 이 예산은 Ingress 단위로 적용되어 초과하는 객체만 제외됩니다. Secret은 50개 단위로 나열하고 응답이 8 MiB를 넘으면 페이지 크기를 절반으로 줄여 다시 시도하며, 캐시는 종류별 64 MiB로 제한됩니다.
