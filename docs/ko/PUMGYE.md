# 품계 서비스 권한 관리

품계의 불변 Rust 코어가 Hangang에 내장됩니다. 호패는 HOP1 인증 신원을,
수문장은 새 네트워크 집행 근거를 제공합니다. 품계는 서비스별 역할·권한·명시적
정보등급·사용자/IP 배정을 소유합니다. 로그인 성공만으로 서비스 권한을 얻지 않습니다.

네이티브 품계 메뉴에서 서비스를 추가하고 호패 사용자 ID와 CIDR에 역할을 배정한
뒤 게시합니다. 미배정 사용자는 guest이며, 세부 guest 대역이 넓은 허용보다 우선합니다.
새 서비스는 기본적으로 수문장 enforce 허용을 요구합니다. JSON 편집기로 역할 상속,
정보등급 집합과 최소 AAL을 설정합니다. 등급 이름에 자동 상하관계는 없습니다.

정책은 Hangang 설정의 `pumgye`에 저장됩니다. 기존 GET/PUT `/v1/config`의
관리자 권한·본문 제한·If-Match CAS·검증·지속 게시·감사를 사용합니다. 다른 설정
필드를 보존하고 동시 변경 시 충돌로 거부합니다. 호패 사용자 DB를 공유하지 않습니다.

보호 HTTP 라우트의 `resource_policy`에 서비스 ID, 정보등급, 메서드별 권한의
`pumgye` 게이트를 연결합니다. 기존 `allow`는 비워야 하고 principal은 external의
`x-forwarded-user`여야 합니다. 네이티브 호패 검증과 `x-forwarded-user`,
`x-hopae-aal` 응답 헤더가 필수입니다. 클라이언트 헤더는 제거하고, 검증 응답의
누락·중복·잘못된 신원/AAL은 거부합니다. 미선언 메서드도 거부합니다.

요청 권한과 등급은 사용자와 신뢰된 소스 IP 배정 모두를 만족해야 합니다. 필수
수문장 집행은 enforce allow만 수용하며 observe·장애·fail-open을 허용하지 않습니다.
짧은 선택 캐시도 우회하여 새 근거를 조회합니다. 수문장 필수를 명시적으로 해제해도
네트워크 차단은 우선합니다.

보호 라우트는 응답 캐시를 우회하고 기존 네임스페이스/정규 경로 방어를 유지합니다.
품계 스트림은 설정 리비전 변경 시 철회되며 프레임별·대기 중 최대 250ms마다
확인합니다. 무관한 설정 게시에도 철회하는 보수적 동작입니다. 긴 스트림에서
프로바이더 세션을 지속 검증한다고 주장하지 않습니다. 활성 게이트 제거는 같은
범위에 `enforce:false`를 먼저 게시해야 합니다.

기존 인증 전용 서비스는 자동 전환하지 않습니다. 보호 라우트와 배정을 명시해야
하며 기능 배포만으로 운영 사용자나 네트워크에 권한을 부여하지 않습니다.
