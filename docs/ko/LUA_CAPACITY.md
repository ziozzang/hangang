# Lua 용량 보고

[문서 목차](../README.ko.md) · [English](../LUA_CAPACITY.md)

경로 Lua 작업은 제한된 프로세스 풀을 사용합니다. 모든 슬롯이 사용 중이거나 워커 실패 후 냉각 중이면 `PolicyPool`은 즉시 거부합니다. 무제한 요청을 대기열에 넣거나 정책을 건너뛰지 않습니다. 워커 수와 마감 시간은 기존 프로세스 설정을 유지합니다. 용량 보고는 요청 대기열을 추가하지 않습니다.

형식화된 `WorkerCapacityUnavailable`으로 거부된 경로 정책 호출에 대해 프록시는 `policy worker capacity exhausted`와 함께 **503**을 반환합니다. 이 요청을 오리진으로 전달하지 않습니다. 스크립트/워커 실패에는 계속 `policy evaluation failed`가 적용됩니다. `Retry-After` 추정값을 임의로 만들지 않습니다.

| 표면 | 필드 | 의미 |
|---|---|---|
| 상태 API 및 SSE | `metrics.policy_capacity_rejections_total` | 모든 슬롯이 사용 중이거나 재시작 중이어서 거부된 경로 Lua 호출의 프로세스 로컬 횟수입니다. |
| Prometheus | `hangang_policy_capacity_rejections_total` | 사용자, 경로 또는 스크립트 레이블이 없는 동일한 카운터입니다. |
| 상태 UI(영어/한국어) | Lua 용량 거부 | 관찰된 카운터입니다. 이전 서버가 이를 제공하지 않으면 `—`이고, 보고된 값이 0일 때만 `0`입니다. |

`policy_errors_total` / `hangang_policy_errors_total`은 기존 집계 의미를 유지하며 용량 거부도 계속 포함합니다. **부분 집계를 전체 집계에 추가하지 마십시오.** Lua 스크립트가 의도적으로 `hangang.reject(...)`를 호출하는 것은 이 용량 이벤트가 아니라 정책 결정입니다. 본문 변환 승인/`PolicyBusy`는 Lua 본문 변환이 기반 워커 풀을 공유하더라도 새 경로 정책 카운터의 범위 밖입니다. 기존 본문 변환 보고는 별도로 유지됩니다.

카운터는 사용률 백분율, 사용 가능한 워커 게이지, 대기열 깊이 또는 플릿 전체 합계가 아닙니다. 워커를 늘리면 리소스 소비가 바뀌며 무제한 동시성을 수립하지 않습니다. 워크로드, 메모리 예산 및 타임아웃 요구 사항에 맞춰 워커 크기를 정하십시오.

소유한 barrier-worker 통합 테스트는 첫 번째 요청이 워커에 도달할 때까지 기다리고, 또 다른 요청을 제출하여 별도 거부와 변하지 않은 오리진 수를 단언한 뒤 워커를 해제하고 이후 요청이 성공함을 증명합니다. 별도 워커 오류는 전체 집계만 증가시킵니다. API/Prometheus 테스트는 같은 카운터 값을 확인하고, 브라우저 테스트는 누락/0 값, SSE 업데이트 및 한국어 레이블을 확인합니다. 이는 정확성 테스트이며 상용 제품 성능 근거가 아닙니다.
