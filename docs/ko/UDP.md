# UDP 라우팅과 QUIC 패스스루

[문서 목차](../README.ko.md) · [한국어 안내](README.md) · [English](../UDP.md)

이 문서는 한국어 보조 요약입니다. 전체 설정과 동작 조건은 [영문 기준 문서](../UDP.md)를 확인하세요.

## 개요

설정의 `udp` 배열로 UDP 리스너와 백엔드를 지정합니다. 새 클라이언트 흐름은 라운드 로빈으로 백엔드를 선택하고 같은 IP·포트의 흐름은 유휴 만료까지 백엔드를 유지합니다. IPv4·IPv6 리터럴 주소, 빈 데이터그램, 크기 제한, 세션 한도, 실행 중 설정 변경을 지원합니다.

`protocol: "quic"`는 암호화된 QUIC 데이터그램을 전달하는 모드입니다. 실제 HTTP/3 백엔드에 연결할 수 있지만, Hangang이 HTTP/3를 종료하거나 암호화된 내용에 HTTP 라우트·Lua·JWT 정책을 적용하지는 않습니다. 연결 ID나 키가 바뀌어도 클라이언트 IP·포트가 같으면 백엔드를 유지합니다. 주소 이동이나 NAT 재바인딩은 새 흐름이므로 다른 백엔드가 선택될 수 있습니다.

## 운영 조건

현재 UDP는 로컬 파일 설정에서 지원하며 공유 저장소·Kubernetes 컨트롤러·감독 모드에서는 거부합니다. UDP/QUIC의 프로세스 간 세션 인계는 구현되어 있지 않습니다. 관련 없는 설정 변경은 흐름을 유지하지만 UDP 라우트 변경·비활성화·삭제·프로세스 종료는 해당 세션을 종료합니다.

흐름당 최대 8개 패킷 대기열과 프로세스 전체 64 MiB의 페이로드·세션 수신 버퍼 예산을 적용합니다. 커널 소켓 메모리 등의 추가 비용은 별도이며 한도 초과 시 데이터그램을 버립니다. 손실 재전송이나 인증은 프로토콜 엔드포인트가 담당합니다.

관리 화면의 **UDP / QUIC** 메뉴에서 추가·수정·삭제·활성화를 수행합니다. 전체 설정 API의 리비전 검사도 적용됩니다. 상태의 `udp_routes`는 설정된 전체 개수, `udp.routes`는 활성 리스너 목록입니다. Docker에서는 별도로 UDP 포트를 게시해야 합니다. 구성 예제와 실제 컨테이너 검증 방법은 [영문 안내](../UDP.md#verification)를 참고하세요.

## 후속 과제: UDP/QUIC 무중단 인계

감독 프로세스 교체 시 UDP/QUIC 연결을 유지하는 기능은 후속 과제로 기록하며, v0.2.0 구현 범위에는 포함하지 않습니다. 리스너 소유권, 백엔드 고정 상태와 업스트림 소켓 매핑을 유지하고, 활성 UDP·QUIC 연결을 대상으로 정상 교체와 교체 실패 시 롤백을 검증해야 합니다. 그전까지 유지보수 시에는 위의 흐름 초기화 조건을 적용합니다.
